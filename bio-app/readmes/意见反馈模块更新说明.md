# 意见反馈模块 — 更新说明

> 更新日期：2026-07-09  
> 关联计划：意见反馈模块实现计划

---

## 1. 更新概述

本次新增**意见反馈**功能，面向普通用户与数据管理员（`role < 9`）开放提交入口；管理员（`role >= 9`）在 Admin Panel 中查看反馈列表并标记处理完成。

交互方式为**侧栏弹窗**，不新增独立页面路由。用户点击菜单时自动记录当前完整 URL，便于定位问题页面。

---

## 2. 功能说明

### 2.1 用户侧（role < 9）

| 项目 | 说明 |
|------|------|
| 入口位置 | 侧栏 `Settings` 之后、`nav-separator` 之前，菜单文案为「意见反馈」 |
| 可见范围 | `role < 9`（普通用户、数据管理员）；管理员账户不显示该入口 |
| 触发方式 | 点击菜单项打开 `van-popup` 弹窗，不跳转页面 |
| 页面 URL | 点击时自动采集 `window.location.href`，表单内只读展示 |

**表单字段：**

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| 意见类型 | 是 | `Bug反馈` / `功能建议` / `其他`（对应 `bug` / `feature` / `other`） |
| 意见文本 | 是 | 多行文本，最多 2000 字 |
| 姓名 | 否 | 默认预填当前用户 `name` |
| 单位名称 | 否 | 默认预填当前用户 `organization` |
| 联系手机号 | 否 | 默认预填当前用户 `phone`；填写时校验格式 |
| 联系邮箱 | 否 | 默认预填当前用户 `email`；填写时校验格式 |
| 图片 | 否 | 最多 10 张，单张 ≤ 5MB；支持 png / jpg / jpeg / webp / gif |

提交成功后弹出提示，并关闭弹窗。

### 2.2 管理侧（role >= 9）

Admin Panel 新增 **Feedback** Tab，提供：

- 可滚动反馈列表（分页，每页 20 条）
- 按状态（`pending` / `completed`）、类型、关键字筛选
- 查看详情：完整意见、联系信息、页面 URL、图片缩略图
- **Mark Completed**：将反馈标记为已完成（`status = completed`，写入 `completed_at`）
- 操作写入 `admin_audit_logs` 审计日志

## 3. API 接口

### 3.1 用户接口

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| POST | `/feedback/submit` | `requireUser`，拒绝 `role >= 9` | 提交意见反馈（`multipart/form-data`） |

**请求字段（form-data）：**

- 文本：`type`、`content`、`page_url`、`contact_name`、`contact_org`、`contact_phone`、`contact_email`
- 文件：`files[]`（多张图片，可选）

**成功响应：** `status: 1`，`options.feedback` 为新建记录。

### 3.2 管理接口

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/admin/feedback` | `requireAdmin` | 分页列表；支持 `status`、`type`、`keyword` 筛选 |
| GET | `/admin/feedback/:id` | `requireAdmin` | 单条详情 |
| PUT | `/admin/feedback/:id/status` | `requireAdmin` | 更新状态，body: `{ "status": "completed" }` |

## 4. 数据库

### 4.1 新增表 `feedbacks`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | INT | 主键 |
| `user_id` | INT | 提交用户，外键关联 `users.id` |
| `type` | VARCHAR(32) | `bug` / `feature` / `other` |
| `content` | TEXT | 意见正文 |
| `page_url` | VARCHAR(2048) | 提交时页面 URL |
| `contact_name` | VARCHAR(100) | 联系人姓名 |
| `contact_org` | VARCHAR(255) | 单位名称 |
| `contact_phone` | VARCHAR(32) | 联系手机 |
| `contact_email` | VARCHAR(255) | 联系邮箱 |
| `images_json` | LONGTEXT | 图片元数据 JSON |
| `status` | VARCHAR(32) | `pending`（默认）/ `completed` |
| `created_at` | TIMESTAMP | 创建时间 |
| `updated_at` | TIMESTAMP | 更新时间 |
| `completed_at` | DATETIME | 标记完成时间 |

### 4.2 Schema 与 SQL

- Prisma 模型：[`api/prisma/schema.prisma`](../api/prisma/schema.prisma)（`Feedback` 模型）
- 独立建表 SQL：[`api/sql/feedbacks.sql`](../api/sql/feedbacks.sql)

### 4.3 图片存储

- 目录：`api/res/feedback/{feedbackId}/`
- 静态访问：`/res/feedback/...`（由 Express 静态资源中间件提供）
- **不计入**用户文件配额（`UserFile` / `UserStorage`）

## 6. 部署与升级步骤

已有环境升级时，按以下顺序操作：

1. **同步数据库结构**

   ```bash
   cd api
   npx prisma db push
   ```

   或手动执行 [`api/sql/feedbacks.sql`](../api/sql/feedbacks.sql)。

2. **重新生成 Prisma Client**

   ```bash
   cd api
   npx prisma generate
   ```

3. **重启后端 API 服务**（默认端口 9092）。

4. **重新构建并部署前端**（如有生产构建流程）。

5. **确认静态目录可写**：确保 `api/res/feedback/` 目录存在且 API 进程有写入权限。

---

## 7. 权限与安全

- 前端：`v-if="!isAdmin"` 隐藏意见反馈入口
- 后端提交：`role >= 9` 调用 `POST /feedback/submit` 返回失败
- 管理接口：统一走 `requireAdmin`
- `page_url` 服务端截断至 2048 字符
- 图片类型与大小在服务端二次校验

---

## 8. 已知限制

- 反馈状态仅支持 `pending` → `completed`，不支持撤销或重新打开
- 管理员账户无前台提交入口（按需求设计）
- 无用户侧「我的反馈」历史查看页面
- 数据库迁移仍依赖 `prisma db push` 或手动 SQL，未纳入 `prisma/migrations/` 版本化目录

## 9. 验收建议

| 场景 | 预期结果 |
|------|----------|
| 普通用户点击「意见反馈」 | 弹窗打开，URL 为当前页面地址 |
| 仅填意见文本并提交 | 提交成功 |
| 上传多张图片 | 图片保存至 `res/feedback/`，详情可预览 |
| 管理员侧栏 | 不显示「意见反馈」菜单项 |
| Admin → Feedback | 列表可滚动，筛选与分页正常 |
| Mark Completed | 状态变为 `completed`，按钮禁用 |
